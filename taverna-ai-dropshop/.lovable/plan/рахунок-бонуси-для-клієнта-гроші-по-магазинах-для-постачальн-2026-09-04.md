# Рахунок: бонуси для клієнта, гроші по магазинах для постачальника

## Проблема, яку видно зараз

На `/wallet` у ролі «Клієнт» показується «Загальний баланс 500₴ / Доступно / В обробці» і кнопки «Поповнити / Вивести». Причина: серверна функція рахунку визначає режим за реальними ролями акаунта (у вас — адмін), а перемикання тестової ролі «жуком» на неї не впливає. Тому клієнтський режим не вмикається.

## Що зміниться

### Клієнт — тільки бонуси
- Жодного грошового балансу, «Доступно», «В обробці», «Поповнити», «Вивести», автовиводу.
- Один блок: бонуси ★, зароблено/витрачено, рейтинг і множник, пропозиції/акції, картка для повернень, історія та чеки лише по замовленнях.
- Нижні кнопки: «Бонуси» + «Оплатити».

### Постачальник — гроші загалом і по магазинах
- Вкладка «Загалом»: сумарний грошовий баланс усіх магазинів + особистий, «В обробці», «Виплачено», оборот, комісія, графік динаміки.
- Вкладка «Магазини»: окремий баланс кожного магазину (доступно / в обробці / виплачено / очікує виплат) і на картці кожного магазину — перемикач **Автовивід** з мінімальною сумою та методом (Telegram Wallet / картка / IBAN). Тобто автовивід налаштовується не лише глобально, а й для кожного магазину окремо.
- Кнопка «Автовивід усім магазинам» у шапці списку — вмикає однакові правила для всіх магазинів одним дотиком.
- Нижні кнопки: «Поповнити», «Вивести», «Оплатити».

### Менеджер магазину
- Тільки перегляд надходжень: суми видно, керування коштами й автовиводом — ні.
- Нижні кнопки: «Надходження» + «Оплатити».

### Гість
- Хмарка й панель — лише «Увійти».

### Адмін / модератор
- Повний вигляд як у постачальника (вкладки Загалом / Магазини / Особистий), плюс перехід до рахунку конкретного магазину з адмін-панелі.

## Технічна частина

- `useWallet.tsx`: режим рахунку рахувати від `effectiveRole` як джерела істини — при `customer/guest` завжди `bonusOnly`, навіть якщо сервер повернув інше; сервер може лише звужувати права, не розширювати. Не перетирати `bonusOnly` відповіддю, якщо роль клієнтська.
- `wallet-account` edge function: приймати `preview_role` (як уже робить `bank-gateway`) і в preview-режимі рахувати `bonus_only` / `read_only` з нього, щоб тестові ролі показували коректний рахунок. Реальні мутації коштів у клієнтському режимі й далі 403.
- `WalletAccount.tsx`: приховати грошову картку, налаштування автовиводу і вкладки магазинів для `bonusOnly`; вкладки Загалом/Магазини лише для ролей із грошима.
- `ShopBalancesList.tsx`: додати на кожну картку магазину блок автовиводу (Switch + мінімальна сума + метод), для менеджера — заблокований стан із замком; додати кнопку масового налаштування автовиводу.
- Автовивід по магазину зберігати через `set_payout_settings` з `supplier_id` (гаманець магазину вже має поля `auto_withdraw`, `auto_withdraw_min`, `payout_provider`).
- `WalletActionBar.tsx` / `WalletBadgeCloud.tsx`: варіанти `guest | bonus | cash | readonly` вже є — вирівняти вибір варіанта з новою логікою ролі, щоб клієнту ніколи не показувались «Поповнити/Вивести».
