# Єдиний рахунок Taverna — фінальна збірка

## Моя оцінка поточного стану

Що вже добре: зелений гаманець у шапці з хмаринкою «$/★», розділення «клієнт = лише бонуси» / «постачальник = кошти», вкладки «Особистий / Магазини», швидкі дії «Поповнити / Вивести / Оплатити».

Що не задовольняє з точки зору клієнта і постачальника:

1. Рахунок ще не єдиний. Паралельно живуть окремі сторінки: `/personal-bonuses`, `/supplier-balance` (+ per-shop), `/my-shops` як фінансовий вхід, а `/bonus-account` лише редіректить. Користувач бачить бонуси в трьох різних місцях і не розуміє, де «правда».
2. Рейтингові бали і нагороди — окремо у вкладці «Рейтинги», хоча це частина рахунку (бали → множники бонусів).
3. У клієнта історія та «Пропозиції» рознесені; акції/промокоди ведуть геть зі сторінки рахунку замість того, щоб бути всередині.
4. У постачальника немає одного екрана «у цілому + по кожному магазину + особисті кошти» — «в цілому» рахується лише у вкладці «Магазини», а особистий баланс живе окремо, без зв'язку зі статистикою.
5. Швидкі дії з хмаринки відкривають форми, але сама сторінка рахунку не має єдиної липкої панелі дій — на довгій сторінці кнопки зникають.

## Що робимо

### Один вхід — `/wallet`
- Усі старі фінансові маршрути стають редіректами на `/wallet`: `/personal-bonuses`, `/bonus-account`, `/supplier-balance` → `/wallet`, `/supplier-balance/:id` → `/wallet/:id`.
- Прибираємо дубльовані пункти меню з профілю та інших екранів, які вели на ці сторінки; лишається один — «Мій рахунок» (зелений гаманець зверху).
- `PersonalBonuses` і `SupplierBalance` як сторінки видаляються; корисні блоки (персональні бонуси, статистика по періодах) переїжджають у рахунок.

### Рахунок клієнта (`bonusOnly`)
Один екран, три секції в одному скролі:
- **Бонуси** — великий баланс ★, зароблено / витрачено, правило «до 7% кошика».
- **Рейтинг і нагороди** — бали, поточний ранг, множник бонусів, прогрес до наступного рівня (дані з рейтингової логіки, без переходу на іншу сторінку).
- **Акції, промокоди, реферали** — компактні картки прямо в рахунку; перехід у каталог акцій лише за потреби.
- **Історія та чеки по замовленнях** — як зараз.
- **Картка для повернень** — як зараз.
Без балансу в ₴, без «в обробці», без «Поповнити/Вивести».

### Рахунок постачальника / адміна
Три вкладки в одному вікні:
- **Загалом** — зведений баланс усіх магазинів + особисті кошти: доступно, в обробці, виплачено, оборот, комісія; графік по періодах (день/тиждень/місяць/рік), перенесений із `SupplierBalance`.
- **Магазини** — список магазинів із балансом і статистикою кожного, тап → рахунок магазину `/wallet/:supplierId`.
- **Особистий** — власний гаманець, Telegram Wallet, автовивід, ліміти, бонуси й рейтинг (постачальник теж клієнт).
Менеджер магазину: лише перегляд надходжень, без сум до виводу і без дій (як зараз, `readOnly`).

### Дії
- Липка нижня панель дій на сторінці рахунку: «Поповнити», «Вивести», «Оплатити» — для ролей із коштами; для клієнта — лише «Оплатити» (перехід у кошик).
- Хмаринка в шапці лишається як зараз, кнопки ведуть у ті самі форми.

## Технічна частина

- `src/pages/WalletAccount.tsx` — рефактор на три вкладки (`overview | shops | personal`) для cash-ролей і єдиний скрол `ClientBonusAccount` для клієнта; додати `WalletActionBar`.
- Нові компоненти: `src/components/wallet/WalletOverview.tsx` (зведення + графік періодів), `src/components/wallet/WalletRatingCard.tsx` (бали, ранг, множник), `src/components/wallet/WalletActionBar.tsx`.
- `src/components/wallet/WalletOffers.tsx` — акції/промокоди/реферали рендеряться як вбудовані картки, посилання на `/personal-bonuses` і `/?tab=ratings` прибираються.
- `src/components/wallet/ClientBonusAccount.tsx` — додати рейтинг-картку та вбудовані пропозиції.
- `src/App.tsx` — редиректи зі старих маршрутів, видалення імпортів `PersonalBonuses`, `SupplierBalance`, `BonusAccount`.
- Оновити навігацію в `Referrals.tsx`, `Promos.tsx`, `RatingsTab.tsx`, `AdminStoreManager.tsx`, `TavernaGroupPanel.tsx`, `ProfileDashboard.tsx`, `MyShops.tsx` на `/wallet` / `/wallet/:id`.
- `src/hooks/useWallet.tsx` — додати агрегати для «Загалом» і серію по періодах (демо-дані для прев'ю зберігаються, щоб усі тестові ролі через «жука» бачили наповнений рахунок).
- Бекенд не змінюємо: `wallet-account` уже віддає гаманець, транзакції, ліміти й зведення магазинів; за потреби додамо лише поле періодної статистики в `get_shops_summary`.
