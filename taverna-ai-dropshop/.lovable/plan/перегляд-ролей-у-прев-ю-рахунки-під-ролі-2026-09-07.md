# Перегляд ролей у прев'ю + рахунки під ролі

## 1. Кнопка «Жук» повертається у прев'ю
Зараз перемикач ролей показується лише справжньому адміну. Додаємо тимчасовий обхід: показувати також, коли додаток відкрито на `localhost` або на домені з `lovable` (прев'ю Lovable). На опублікованому власному домені для не-адмінів кнопки не буде.

## 2. Рахунок клієнта — тільки бонуси
Для ролі «Клієнт» і «Гість»:
- жодних гривневих сум, «Поповнити», «Вивести», вкладки «Магазини»;
- лише зірочки-бонуси, рейтинг/ранг, історія та чеки по замовленнях, картка для повернень;
- у зеленому гаманці зверху — тільки ★ і кнопки «Бонуси» / «Оплатити» (гість — «Увійти»).

## 3. Рахунок постачальника — три вкладки
- «Загалом» — сума по всіх магазинах + особистий гаманець, з чітким поділом «Доступно» і «В обробці» (кошти, що чекають завершення замовлень).
- «Магазини» — список магазинів, у кожного своя сума «Доступно» і «В обробці», автовивід.
- «Особистий» — власний гаманець, поповнення, вивід, налаштування.
Скрізь, де показується сума, поруч буде окремо підписано, скільки вже доступно, а скільки ще в обробці (з підказкою, що це кошти по незавершених замовленнях).

## 4. Розумне вікно виводу
Коли постачальник тисне «Вивести» із загального балансу, спершу треба обрати джерело: випадний список «Оберіть магазин для списання» з сумою «Доступно» біля кожного магазину (плюс пункт «Особистий гаманець»). Без вибору джерела кнопка виводу неактивна. Сума обмежується доступним залишком обраного джерела; комісії й «отримаєте на руки» рахуються як зараз.

## Технічна частина
- `TelegramAuthProvider.tsx`: `canUseDevRoleSwitcher = isRealAdmin || hostname includes 'lovable' || 'localhost'` (через `isPreviewDevEnvironment()` з `src/lib/dev-preview.ts`). `FloatingDevRoleSwitcher.tsx` лишається без змін (споживає той самий прапорець).
- `WalletAccount.tsx`: для `bonusOnly` (customer/guest) — не рендерити вкладки й грошові блоки взагалі (`hasShops` не застосовується), тільки `ClientBonusAccount`. Ігнорувати `?tab=`/`?action=topup|payout` з пояснювальним toast (вже є).
- `WalletBadgeCloud.tsx` / `Header.tsx`: варіант `bonus` не показує `$`; перевірити, що `cash` доступний лише `supplier/admin/moderator`.
- Вкладка «Загалом» (`WalletOverview.tsx`) і `ShopBalancesList.tsx`: винести пару «Доступно / В обробці» в однаковий компонент-рядок з бейджем-годинником для холдів.
- `PayoutSheet.tsx`: новий проп `sources` (магазини-власники + особистий), shadcn `<Select>` з підписом суми «Доступно», валідація `amount <= source.available`, передача `shop_id` у `onPayout`; для виводу з `/wallet/:supplierId` джерело фіксоване.
- Без змін у RLS та edge-функціях (крім передачі вже наявного `shop_id` у payload виводу, якщо він підтримується; інакше — залишаємо поточний виклик).
