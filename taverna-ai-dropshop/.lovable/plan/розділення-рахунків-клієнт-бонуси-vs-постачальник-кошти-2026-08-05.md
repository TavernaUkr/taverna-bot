# Розділення рахунків: Клієнт (бонуси) vs Постачальник (кошти)

## Що змінюється

### Клієнт — тільки бонуси
- У «Мій рахунок» клієнт бачить один блок: **Бонусний баланс** (★) + скільки зароблено/витрачено.
- Прибрати для клієнта: загальний баланс у гривні, «Доступно», «В обробці», кнопки «Поповнити» / «Вивести», банер підключення Telegram Wallet, налаштування автовиводу.
- Історія — лише рухи, пов'язані із замовленнями (нарахування бонусів за замовлення/відгук, списання бонусів на замовлення, повернення). Чек відкривається як чек по замовленню.
- Залишаються акції/пропозиції та промокоди (блок «Пропозиції»).
- У шапці (зелений гаманець) для клієнта: тільки ★ з бонусами, без «$», без кнопок «Поповнити»/«Вивести». Лишається «Оплатити» (перехід у кошик), бо це не про баланс.

### Клієнт — картка для повернень
- Новий пункт у Налаштуваннях профілю: **«Картка для повернень»** — номер картки або IBAN + ПІБ отримувача. Використовується, якщо замовлення повертається або щось пішло не так.
- Номер зберігається у замаскованому вигляді (показуємо `**** **** **** 1234`), редагування/видалення доступні власнику.

### Постачальник (і адмін/модератор) — повний рахунок
- Без змін по суті: загальний баланс, доступно/в обробці, поповнення, вивід, автовивід, Telegram Wallet, ліміти, чеки, вкладка «Магазини» зі статистикою.
- Менеджер магазину — як зараз: тільки перегляд надходжень, без доступу до коштів.

### Оплата замовлення
- Клієнт не платить «балансом Taverna» — лише бонусами (у межах чинного ліміту 7% від кошика) + звичайні методи оплати. Метод «Taverna Balance» у чекауті лишається тільки для ролей із реальним рахунком.

## Технічна частина

- `useWallet` — додати похідний прапорець режиму рахунку (`bonusOnly`) на основі ролі; для клієнта не тягнути ліміти/шопи й не показувати грошові поля.
- `WalletAccount.tsx` — рендер двох варіантів сторінки: `ClientBonusAccount` (бонуси + історія по замовленнях + пропозиції) і чинний повний вигляд для постачальника/адміна. Дії `?action=topup|payout` ігноруються для клієнта.
- `WalletBadgeCloud` / `Header.tsx` — приховати `$` та кнопки поповнення/виводу для клієнта.
- `wallet-account` edge function — серверна перевірка: для ролі `customer` дії `create_topup`, `request_payout`, `set_payout_settings`, `connect_wallet` повертають 403; `get_account` віддає лише бонусний блок і транзакції типів `bonus_earn`/`bonus_spend`/`refund`, прив'язані до замовлень.
- Міграція: таблиця `refund_methods` (profile_id, тип card/iban, маскований номер, токен/значення, holder) з GRANT + RLS «тільки власник», плюс доступ service_role для функцій виплат.
- Нова сторінка `src/components/settings/RefundMethodPage.tsx` + пункт у `SettingsMainPage.tsx`.
- `WalletPayment` у чекауті — приховати оплату балансом для клієнта, залишити бонуси.
