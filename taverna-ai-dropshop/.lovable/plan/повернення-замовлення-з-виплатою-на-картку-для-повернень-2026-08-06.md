# Повернення замовлення з виплатою на «Картку для повернень»

## Що зараз є

- У деталях замовлення кнопка «Повернення» лише відкриває AI-чат з темою `return` — жодного запису про повернення не створюється.
- У профілі клієнта вже є «Картка для повернень» (картка/IBAN), яка зберігається окремо і поки ніяк не пов'язана із замовленнями.
- Статус `return` у списку замовлень існує лише як мітка, без суми й без прогресу виплати.

## Що буде реалізовано

### 1. Заявка на повернення (клієнт)
- У деталях замовлення кнопка «Оформити повернення» відкриває форму: які позиції повертаються, причина, коментар.
- Форма одразу показує збережену «Картку для повернень» (`**** 4242 · Іван Петренко`). Якщо реквізитів немає — блок із кнопкою «Додати картку», без неї заявку відправити не можна.
- Сума повернення рахується автоматично: вартість обраних позицій + доставка, якщо повертається все замовлення й сума > 1500 ₴ (чинне правило безкоштовного повернення). Бонуси, витрачені на замовлення, повертаються на бонусний рахунок пропорційно.
- Після відправки замовлення отримує статус «Повернення» і в ньому з'являється блок повернення.

### 2. Відображення в історії замовлення
- У картці замовлення — бейдж «Повернення · 2 340 ₴».
- У деталях — блок «Повернення коштів» з таймлайном: Заявка створена → На перевірці → Схвалено → Виплачено (з датою) або Відхилено з причиною.
- Показуються: сума, реквізити виплати (замасковані), повернені бонуси, номер транзакції після виплати.
- Чек замовлення доповнюється рядком «Повернуто -X ₴».

### 3. Обробка (модератор/адмін)
- У «Спорах» модератора нова черга «Повернення»: список заявок із сумою, реквізитами клієнта та кнопками «Схвалити виплату» / «Відхилити (з причиною)».
- Після схвалення створюється рух коштів: списання з балансу магазину-постачальника, запис у транзакції клієнта типу `refund` з прив'язкою до замовлення, статус заявки → «Виплачено».
- Клієнт бачить цей рух у «Мій рахунок» (історія по замовленнях), як і передбачено бонус-онлі рахунком.

### 4. Тестовий режим
- Для preview/жука додаються демо-заявки на повернення (в обробці, схвалена, виплачена, відхилена), щоб можна було переглянути всі стани без бекенду.

## Технічна частина

- Міграція: таблиця `public.order_refunds` (`order_id`, `profile_id`, `supplier_id`, `refund_method_id`, `items jsonb`, `amount`, `bonus_amount`, `reason`, `comment`, `status` = requested|approved|paid|rejected, `rejection_reason`, `transaction_id`, `paid_at`, timestamps) + GRANT (`authenticated` select/insert, `service_role` all) + RLS: клієнт бачить і створює лише свої записи, зміна статусу — тільки через service_role; модератор/адмін читають через `has_role`. Тригер `updated_at`.
- Edge function `order-refunds` (session-token валідація як у `wallet-account`): `create_request` (перевіряє власника замовлення, наявність `refund_methods`, 14-денне вікно, рахує суму на сервері — клієнтську суму не приймаємо), `list_my_refunds`, `list_pending` (moderator/admin), `set_status` (approve/reject/mark_paid → створює `wallet_transactions` type `refund` і рух по `shop_balances`/`balance_movements`).
- Фронтенд:
  - `src/components/orders/RefundRequestSheet.tsx` — форма заявки з підтягнутою карткою повернення (через існуючий `get_refund_method`).
  - `src/components/orders/RefundStatusBlock.tsx` — таймлайн у деталях замовлення.
  - `OrdersHistory.tsx` — кнопка «Оформити повернення» замість прямого чату, бейдж суми, підвантаження заявок одним запитом, демо-дані для preview.
  - `ReceiptDialog.tsx` — рядок повернення.
  - `DisputesManager.tsx` — вкладка «Повернення» з діями схвалити/відхилити.
